# Uptime-Kuma-Web-API 3.0.0-rc.1

First release candidate of 3.0: the API rewritten in Go for **Uptime Kuma 2.x**, with the routes,
bodies, status codes, environment variables and `/db` volume of 2.0.

```bash
docker pull medaziz11/uptimekuma_restapi:v3.0.0-rc.1
```

This release candidate is not tagged `latest`, `v3` or `v3.0`.

## Upgrading from 2.0

Uptime Kuma must be 2.x: the acceptance suite passes on 2.0.0, 2.4.0, 2.5.0 and 2.5.11 (the
incident history routes need 2.1.0 or later and answer 501 before). Swap the image
tag and keep the environment and the `/db` volume: users, passwords and tokens issued by 2.0 keep
working, and the container runs as the same uid/gid as 2.0. Every difference from 2.0, what a client
must change and how to roll back: [docs/migration-2-to-3.md](https://github.com/MedAziz11/Uptime-Kuma-Web-API/blob/v3.0.0-rc.1/docs/migration-2-to-3.md).

Uptime Kuma 1.x users stay on 2.x (`medaziz11/uptimekuma_restapi:v2`), which receives security
fixes only.

## Highlights

- New routes for Uptime Kuma 2.x: API keys, remote browsers, incident history, chart data,
  important heartbeats, push monitor examples.
- Reads answered from memory with `ETag`/`304`; 5,000 req/s on `GET /monitors` with 200 monitors
  on the test machine, where 2.0 saturated at about 5 req/s
  ([measurements](https://github.com/MedAziz11/Uptime-Kuma-Web-API/blob/v3.0.0-rc.1/docs/performance.md), including the targets that are not met).
- Image of 6.5 MB compressed, no shell, SBOM and provenance attestation.
